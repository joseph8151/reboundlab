# Afterline 운영 안내

신청부터 상담까지 쓰는 문자 템플릿과 체크리스트입니다. `[ ]`는 상황에 맞게 채웁니다.

---

## 1. 흐름

| 단계 | 할 일 | 문자 |
|---|---|---|
| 신청 접수 | 신청 내용 확인, 상담 상품 판단 | ① 입금 안내 |
| 입금 확인 | 입금자명과 금액 대조 | ② 일정 확정 |
| 상담 전날 | 일정 다시 안내 | ③ 전날 안내 |
| 상담 당일 | 약속 시간에 상담 전용 번호로 발신 | (연결 안 될 때) ④ 부재 안내 |
| 상담 후 | 정한 행동 요약 전달 | ⑤ 상담 후 정리 |

- 입금 기한이 지나도록 입금이 없으면 ⑥ 신청 취소 문자를 보냅니다.
- 모든 문자와 전화는 **상담 전용 번호**로만 보냅니다. 개인 번호나 발신번호 표시제한(`*23`)은 쓰지 않습니다.

---

## 2. 문자 템플릿

### ① 입금 안내

```
[Afterline] 상담 신청이 접수되었습니다.

· 상담: [상품명]
· 금액: [금액]원
· 입금 계좌: [은행] [계좌번호] ([예금주])
· 입금자명: 이름+전화번호 뒤 4자리 (예: 홍길동1234)
· 입금 기한: [M월 D일 H시]까지

입금이 확인되면 통화 일정을 안내드립니다.
현금영수증이 필요하시면 이 번호로 알려 주세요.
```

### ② 일정 확정

```
[Afterline] 입금이 확인되었습니다.

· 상담 일시: [M월 D일 (요일) H시 M분]
· 상담 시간: [ ]분
· 전화드릴 번호: [상담 전용 번호]

번호를 저장해 두시면 전화를 놓치지 않습니다.
상담 전 필요한 대화 캡처가 있다면 상대의 이름과 사진은 가린 뒤 준비해 주세요.
일정 변경은 상담 [ ]시간 전까지 가능합니다.
```

### ③ 전날 안내

```
[Afterline] 내일 [H시 M분]에 [상담 전용 번호]로 전화드립니다.
통화가 편한 장소에서 받아 주세요.
```

### ④ 부재 안내

```
[Afterline] 약속한 시간에 전화드렸으나 연결되지 않았습니다.
[ ]분 뒤에 한 번 더 전화드리겠습니다.
```

### ⑤ 상담 후 정리

```
[Afterline] 오늘 상담에서 정한 내용입니다.

· 지금의 방향: [연락 / 대기 / 정리]
· 다음 행동: [한 문장]
· 하지 않을 것: [한 문장]
· 다시 볼 시점: [M월 D일 무렵]

상황이 바뀌면 이 번호로 알려 주세요.
```

### ⑥ 신청 취소

```
[Afterline] 입금 기한이 지나 상담 신청이 취소되었습니다.
다시 신청하시려면 홈페이지에서 접수해 주세요.
```

---

## 3. 문자 쓸 때 지킬 것

- 상담 내용(이별 사정, 상대 이야기)은 문자에 쓰지 않습니다. 휴대폰을 다른 사람이 볼 수 있습니다.
- 위로나 결과 예측 문장을 넣지 않습니다. "잘될 거예요", "연락 올 거예요" 같은 말입니다.
- 계좌번호는 홈페이지에 올리지 않고 ① 문자로만 보냅니다.

## 4. 시작 전 체크리스트

- [ ] 상담 전용 번호 개통 (통신사 투넘버 또는 070)
- [ ] 사업자등록, 사업자 명의 계좌
- [ ] 통신판매업 신고 필요 여부 확인
- [ ] 현금영수증 의무 발행 업종인지 세무사 확인
- [ ] 상품별 가격, 상담 1회 시간 확정
- [ ] 환불 기준 시간 확정 → `site/build.py`의 TERMS, 홈 FAQ에 반영
- [ ] 자료 보관 기간 확정 → `site/build.py`의 PRIVACY에 반영
- [ ] 개인정보처리방침과 이용약관 전문가 검토
- [x] 신청서 접수 연결 (Cloudflare D1, 아래 5장)
- [ ] Cloudflare 프로덕션 브랜치, `ADMIN_PASSWORD` 시크릿, 주소 설정 (아래 5장)
- [ ] 도메인 확정 → `site/build.py`의 `DOMAIN` 변경 후 `python3 build.py`

## 5. 배포와 신청 관리 (Cloudflare)

사이트와 신청서 접수는 Cloudflare Worker `reboundlab` 하나로 돌아갑니다.

| 구성 | 위치 |
|---|---|
| 정적 페이지 | `site/` |
| 신청 접수, 관리자 화면 | `src/worker.js` |
| 배포 설정 | `wrangler.jsonc` |
| 데이터베이스 | D1 `afterline` (표: `applications`, 정의: `migrations/`) |
| 신청서 항목 | `src/form_fields.json` (화면과 서버 검증이 함께 씀) |

**처음 한 번 할 일 (Cloudflare 대시보드)**
1. Workers & Pages → `reboundlab` → Settings → Build에서 **프로덕션 브랜치**를 배포할 브랜치로 맞춥니다.
2. Settings → Variables and Secrets에서 **시크릿** `ADMIN_PASSWORD`를 추가합니다. 관리자 화면 비밀번호입니다.
3. Settings → Domains & Routes에서 `workers.dev`를 켜거나, 커스텀 도메인을 연결합니다.

**신청 확인**
- `https://[사이트 주소]/admin` 에 접속합니다. 아이디는 아무거나, 비밀번호는 `ADMIN_PASSWORD`입니다.
- 상태를 `접수 → 입금 대기 → 일정 확정 → 상담 완료` 순서로 바꿔 가며 관리합니다. 취소는 `취소`로 둡니다.
- 시간은 한국 시간으로 표시됩니다.

**페이지를 고친 뒤**
- Column이나 약관을 고쳤다면 `python3 site/build.py`를 실행한 뒤 커밋합니다. 원고는 `site/columns_data.py`, `site/legal_data.py`에 있습니다.
- 푸시하면 Cloudflare가 자동으로 다시 배포합니다.

**새 신청 이메일 알림 (Formspree)**
1. formspree.io에 가입하고 **New Form**을 만듭니다. 알림 받을 이메일을 넣습니다.
2. 폼 주소 `https://formspree.io/f/abcdwxyz`에서 마지막 부분(`abcdwxyz`)이 폼 ID입니다.
3. 폼 ID는 `wrangler.jsonc`의 `vars.FORMSPREE_FORM_ID`에 들어 있습니다(현재 `moejjwqa`). 폼을 바꾸면 이 값을 고친 뒤 푸시합니다.
4. 신청이 들어오면 D1에 저장된 뒤, 같은 내용이 이메일로 옵니다. 알림이 실패해도 신청은 `/admin`에 남아 있습니다.
5. 첫 신청이 들어오면 Formspree에서 확인 메일이 올 수 있습니다. 확인을 눌러야 이후 알림이 옵니다.

**신청서 항목 바꾸기**
1. `src/form_fields.json`에서 항목이나 선택지를 고칩니다.
2. `python3 site/build.py`를 실행하면 `site/index.html`의 신청서가 다시 만들어집니다.
3. 커밋하고 푸시하면 화면과 서버 검증이 함께 바뀝니다. 새 항목은 `details` 열(JSON)에 저장되므로 데이터베이스를 고칠 필요가 없습니다.

**재회 가능성 진단 (`/check/`)**
- 화면: `site/check/index.html`(build.py가 생성) · 질문과 점수 규칙: `site/check/check.js`
- 계산은 브라우저에서만 합니다. 답변은 서버로 보내지 않고, 진행 중에만 브라우저(localStorage)에 임시 저장합니다.
- 점수 축 5개(관계 기반 15%, 연락의 여지 15%, 현재 반응 25%, 변화 가능성 25%, 재접촉 준비도 20%)를 0~100으로 정규화해 합칩니다. SNS는 ±3점까지만 반영하고, 최종 지표는 95를 넘지 않습니다.
- 반드시 지키는 조건: 안전 문제 → 점수 없이 안전 안내만 / 명확한 연락 거부 → 24 이하, WAIT / 반복 연락과 무응답 → 44 이하, WAIT / 상대의 새 연애 → 44 이하(거절 신호가 있으면 24 이하), 개입 전략 제안 없음
