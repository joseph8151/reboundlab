# AFTERLINE Column 편성

원고는 `site/columns_data.py`(새 칼럼)와 `site/articles_data.py`(이전 아티클)에 있습니다.
고친 뒤 `python3 site/build.py`를 실행하면 `site/column/`이 다시 만들어집니다.

## 원칙
- 한 편은 하나의 상황만 다룹니다.
- 글마다 구조를 다르게 씁니다. 비교표, 질문 목록, 나란히 놓기, 메시지 나눠 보기처럼 상황에 맞는 형식을 고릅니다.
- 검색 키워드(재회상담, 차단 후 재회, 이별 후 연락, 재회 공백기, 전남친 재회, 전여친 재회, 카톡 분석, 차단 해제 후 연락, 이별 직후 연락, 재회 후 관계)는 제목과 본문에 자연스럽게만 씁니다. 홈 화면과 카테고리 이름에는 나열하지 않습니다.
- 재회 확률, 상대 심리 단정, 연락 유도 문장은 쓰지 않습니다.

## 카테고리
ALL · 차단 이후 · 이별 후 연락 · 공백기 · 마지막 대화 · SNS와 신호 · 재접촉 · 반복되는 관계 · 재회 이후 · 이별 직후

## 새로 쓴 칼럼 (8편, 구조가 각각 다름)
| 카테고리 | 제목 | 형식 |
|---|---|---|
| 차단 이후 | 차단이 풀렸는데 연락은 없습니다. 무엇이 달라진 걸까요 | 가능성 목록 + 판단에 쓰는 것/쓰지 않는 것 |
| 마지막 대화 | 마지막 카톡이 '잘 지내'로 끝났을 때 | 두 장면 비교 |
| 공백기 | 한 달을 기다리는 것보다 먼저 확인해야 할 것 | 세 가지 질문 |
| 이별 후 연락 | 생일이 다가오는데 먼저 연락해도 될까요 | 보내도 되는 경우/아닌 경우 |
| SNS와 신호 | 스토리를 계속 보는 행동은 판단 근거가 될 수 있을까요 | 짧은 에세이 |
| 재회 이후 | 다시 만났는데 이전보다 연락이 더 불편해졌다면 | 원인 + 대화 예시 |
| 반복되는 관계 | 세 번째 재회라면 연락 시점보다 먼저 봐야 할 것 | 세 번의 이별 나란히 놓기 + 질문 |
| 이별 직후 | 헤어진 다음 날 보내고 싶은 긴 메시지 | 메시지를 네 가지로 나눠 보기 |

## 이전 아티클 (20편)
같은 틀(장면 → 먼저 확인할 것 → 하지 않아도 되는 것 → 다음 행동)로 쓰여 있습니다. 순서대로 새 형식으로 다시 쓰는 것을 권합니다.
